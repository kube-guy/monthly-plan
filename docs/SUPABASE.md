# Supabase 연결

## 1. 프로젝트 준비

Supabase 조직에서 `monthly-plan` 전용 프로젝트를 선택하거나 생성합니다. 조직 주소(`/dashboard/org/...`) 자체는 앱에 입력할 프로젝트 URL이 아닙니다. 프로젝트 생성 시 지역, 요금제와 사용량 한도를 직접 확인하세요.

## 2. 데이터베이스 설정

프로젝트의 **SQL Editor**에서 [`supabase/migrations/202609280001_initial.sql`](../supabase/migrations/202609280001_initial.sql) 전체를 새 쿼리에 붙여 넣고 실행합니다. 빈 프로젝트에 한 번 적용하는 초기 마이그레이션입니다. 기존 테이블을 지우거나 덮어쓰지 않습니다. 이미 적용했다면 반복 실행하지 마세요.

이어서 [`supabase/migrations/202609290001_place_summaries.sql`](../supabase/migrations/202609290001_place_summaries.sql)을 한 번 실행합니다. 기존 프로젝트도 이 두 번째 마이그레이션이 있어야 장소 요약을 Mac 간에 저장·동기화할 수 있습니다. 기존 일정 행은 변경하지 않습니다.

이 SQL은 다음을 만듭니다.

- `monthly_plan_records`: 일정, 장소 연결 ID, 저장된 장소 요약, 버전, 삭제 기록
- RLS: 로그인한 사용자가 자신의 행만 조회할 수 있음
- `monthly_plan_push`: 자신의 데이터만 버전을 비교하여 수정하는 함수
- 익명 사용자의 읽기·쓰기, 로그인 사용자의 직접 테이블 쓰기 차단

`service_role`이나 `sb_secret_...` 키는 앱에 넣지 않습니다. 함수는 로그인 토큰의 사용자 ID를 사용하며 요청자가 다른 사용자 ID를 전달할 수 없습니다.

## 3. 앱 사용자 로그인 설정

**Authentication → Providers / Sign In**에서 이메일 로그인을 활성화합니다. 무료 기본 메일 템플릿을 그대로 사용할 수 있습니다.

**Authentication → URL Configuration → Redirect URLs**에 다음 주소를 추가합니다.

```text
monthly-plan://auth/callback?state=*
```

앱에서 로그인 메일을 요청하고 **같은 Mac에서** 메일의 **Sign in / Confirm your mail** 링크를 클릭합니다. 브라우저에서 monthly-plan 열기를 허용하면 앱으로 돌아와 로그인이 완료됩니다. 앱은 열린 상태로 두세요. 로그인 요청은 15분 동안 유효하며, PKCE와 요청별 state로 이 Mac에서 시작한 인증인지 확인합니다. 액세스 토큰을 리디렉션 URL로 받지 않습니다.

앱이 열리지 않으면 **아직 클릭하지 않은 최신 메일의 원본 로그인 링크**를 복사해 앱의 보조 입력칸에 붙여 넣을 수도 있습니다. 이미 브라우저에서 사용한 메일 링크는 재사용할 수 없습니다. 앱이 종료되었거나 링크가 만료된 경우 새 메일을 요청하세요. 링크와 인증번호를 다른 사람이나 채팅에 공유하지 마세요.

숫자 인증번호 방식이 필요하면 사용자 SMTP를 설정한 뒤 **Email Templates → Magic Link**의 본문에 `{{ .Token }}`을 넣으세요. 무료 기본 메일 서비스는 템플릿 편집을 제한할 수 있습니다. 실제 메일 전달에는 프로젝트의 발송 제한과 SMTP 설정을 확인하세요. 기본 서비스는 수신자 제한이 있을 수 있으며 공개 배포에는 자신의 SMTP 공급자를 연결하는 것이 좋습니다. CAPTCHA를 요구하는 프로젝트 구성은 현재 앱에서 지원하지 않습니다.

Supabase 대시보드에 GitHub로 로그인해도 됩니다. 그것은 프로젝트를 관리하는 계정이며 앱 사용자 로그인과 별개입니다.

## 4. 각 Mac에서 연결

프로젝트의 **Connect** 또는 **Settings → API Keys**에서 프로젝트 URL과 **publishable key**(이전 프로젝트는 **anon key**)를 확인합니다.

1. 앱 상단 **클라우드 연결**을 엽니다.
2. `https://<project-ref>.supabase.co`와 공개 키를 입력하고 **프로젝트 연결**을 누릅니다.
3. 이메일을 입력하고 **로그인 메일 받기**를 누릅니다.
4. 같은 Mac에서 새 메일의 링크를 열고 monthly-plan으로 돌아옵니다. 숫자 코드는 보조 입력칸을 사용할 수 있습니다.
5. 다른 Mac에서도 같은 프로젝트와 같은 이메일을 사용합니다.

설정값은 저장소에 커밋하지 않아도 됩니다. 로그인 토큰은 Mac 키체인에 보관합니다. 클라우드 연결 전 일정은 **이 Mac의 기존 일정 가져오기**로 명시적으로 복사합니다.

## 동기화 규칙

- 서버 버전 비교로 동시 수정을 감지하며 기기의 시계에 의존하지 않습니다.
- 동일한 변경을 재전송해도 동일 mutation ID를 통해 중복 적용하지 않습니다.
- 전송 중에 새로 편집한 내용은 기존 요청의 완료로 지워지지 않습니다.
- 삭제는 tombstone으로 남겨 오랫동안 오프라인이던 기기에도 전달합니다. 기기 관리와 정리 정책 없이 tombstone을 직접 삭제하지 마세요.
- 충돌은 두 버전을 보존하고 사용자가 선택합니다. 그사이 다른 수정이 있었다면 다시 충돌할 수 있습니다.
- 계정별로 데이터를 격리합니다. 사용자 간 공유 기능은 포함하지 않습니다.
- 같은 장소의 첫 요약은 계정별로 저장하며, 이미 저장된 요약은 다른 Mac에서 다시 Codex로 조회하지 않습니다. 동시에 두 Mac이 처음 열었다면 먼저 서버에 저장된 요약을 채택합니다.
- 앱이 켜진 동안 약 60초마다 확인하며, '지금 동기화'로 바로 요청할 수 있습니다.

## 확인할 항목

두 Mac 또는 분리된 테스트 사용자 환경에서 일정 생성·수정·삭제, 오프라인 변경 후 재접속, 동시 수정 충돌을 확인하세요. 사용자 A의 데이터를 사용자 B가 조회하지 못하는지도 검사해야 합니다. 로컬 검사만 통과했다고 실제 프로젝트 설정이 완료된 것은 아닙니다.
